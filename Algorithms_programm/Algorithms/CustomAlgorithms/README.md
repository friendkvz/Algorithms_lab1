# CustomAlgorithms — точка расширения для Части III методички

Сюда добавляются 1–2 нетривиальных пользовательских алгоритма, не пересекающихся
с Частями I, II, IV.

## Как добавить новый алгоритм

1. Реализуйте `ITimedAlgorithm<TInput, TResult>` (если измеряется время) или
   `IStepCountingAlgorithm<TInput, TResult>` (если измеряются операции, как в Части IV).
2. Если для алгоритма нужен новый тип входных данных, добавьте DTO рядом (по аналогии
   с `MatrixPair` в `MatrixOperations` или `PowerInput` в `PowerAlgorithms`).
3. Если нужна собственная генерация данных под размер n — добавьте метод в
   `DataGeneration` (по аналогии с `VectorGenerator`/`MatrixGenerator`).
4. Зарегистрируйте алгоритм в реестре алгоритмов GUI/оркестратора (появится на Этапе GUI —
   `Services/AlgorithmRegistry`), чтобы он отобразился в выпадающем списке приложения.
5. Добавьте юнит-тест корректности в `Algorithms_Tests/Algorithms/CustomAlgorithms/`.

Пример-заготовка (`HanSortAlgorithm.cs`) — целочисленная поразрядная (radix) сортировка,
практическая реализация в духе линии работ Yijie Han по детерминированной целочисленной
сортировке за пределами O(n log n) сравнений (подробности и оговорки — в комментарии
к классу). Вход — `int[]` неотрицательных чисел, а не `double[]`, как у алгоритмов 5–7,
поэтому под него нужен отдельный целочисленный генератор данных
(`DataGeneration/IntegerVectorGenerator.cs`). Замените/дополните его собственным заданием —
он не является обязательной частью лабораторной, а лишь демонстрирует, как использовать
точку расширения для алгоритма с нестандартным типом входных данных.
